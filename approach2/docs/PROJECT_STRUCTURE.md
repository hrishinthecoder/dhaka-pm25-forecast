# Project Structure — Dhaka Next-Day PM2.5 Forecasting

End-to-end pipeline that forecasts the **next-day (t+1) 24-hour mean PM2.5** at a single
Dhaka reference station, with a secondary next-day **US-EPA AQI category**. It ingests
ground-truth and meteorological data, builds leakage-safe daily features, trains and
compares baselines + tree ensembles, evaluates with paired significance tests and a
multi-year rolling backtest, then freezes the published XGBoost model with checksums.

Data flows in one direction:

```
ingest (notebook 01 + src/ingest)  ->  data/processed/*.parquet
        |                                     |
        v                                     v
features (src/features)  ->  models (src/models)  ->  evaluate (src/evaluate)  ->  reports/ + models/
                                                                                        |
                                                                            freeze (src/freeze_model)
                                                                                        |
                                                                  models/final/ + src/predict + app/
```

## `config/` — configuration (source of truth for every knob)

| File | Contents / role |
|---|---|
| `sources.yaml` | Ingest configuration: area of interest, date range (2016–2025), OpenAQ station-discovery rules, Open-Meteo / FIRMS parameters. Consumed by notebook 01 and `src/ingest/*`. |
| `stations_resolved.yaml` | The reference-grade OpenAQ station/sensor IDs resolved during discovery (pinned for reproducibility). |
| `model.yaml` | Modeling contract: target framing (Option A, next-day daily mean), coverage rule (≥18 hourly obs/day, both-days-valid), temporal split (train ≤2023 / val 2024 / test ≥2025), feature lists, model grids, evaluation settings, and **seed 42**. Read by everything under `src/{features,models,evaluate}` and `run_experiment.py`. |

## `src/` — pipeline code

### `src/ingest/` — data acquisition + master assembly
| File | How it works |
|---|---|
| `openaq.py` | Pulls hourly ground-truth PM2.5 (+ o3/pm10/etc.) from OpenAQ v3 for the resolved reference-grade sensors. Caches raw responses under `data/raw/openaq/` (monthly windows, resilient to API timeouts). PM2.5 is the **target**; o3/pm10 are later excluded as predictors. |
| `open_meteo.py` | Fetches ERA5 reanalysis meteorology (temp, RH, dew point, pressure, cloud, wind, precip, radiation, **BLH**) at the city centroid. Year-chunked, cached under `data/raw/open_meteo/`. |
| `firms.py` | Pulls NASA FIRMS active-fire count + summed FRP (5-day windows, the API cap), cached under `data/raw/firms/`. |
| `calendar_features.py` | Pure (no API): day_of_week, month, weekend, holiday, Ramadan, cyclical encodings. |
| `merge.py` | Assembles the continuous hourly UTC master: collapses stations **(covariates only — the PM2.5 target is single-sensor 24434, see `fusion/swap_target.py`)**, left-joins all sources, runs `_impute_blh` (train-only ≤2023 climatology fallback), then **auto-invokes the CDS BLH patch** (`patch_frame`) before writing `data/processed/dhaka_aq_master_rebuilt.parquet` (+ csv). |
| `cds_blh.py` | **PATH A**: pulls *true* ERA5 boundary-layer height for the 2024-01-01→06-30 window directly from the Copernicus CDS (the gap exists only in the Open-Meteo mirror). Reuses the cached `data/interim/era5_blh_cds.nc` if present (no re-request). |
| `patch_blh.py` | Orchestrates the BLH gap fix. `patch_frame(df)` auto-selects PATH A (CDS native, sets `era5_blh_imputed=0`) when credentials exist, else PATH B (train-only climatology, `era5_blh_imputed=1`) and prints a **checksum-mismatch WARNING**. Shared by `merge.py` and the standalone `python -m src.ingest.patch_blh`. |

### `src/features/`
| File | How it works |
|---|---|
| `daily.py` | Builds the **45** leakage-safe daily features (PM2.5 history lags/rolling, ERA5 mean/min/max + sums, wind vector decomposition, FIRMS lags, calendar). Enforces hard leakage guards (no t+1, no same-station o3/pm10, no satellite PM2.5; raises if any leak in). Defines the Option-A target (joint ≥18h rule), AQI binning, and `feature_availability()` (forecast-validity proof). |

### `src/models/`
| File | How it works |
|---|---|
| `train.py` | `baselines()` (persistence + day-of-year climatology), `fit_scaler`/`apply_scaler` (StandardScaler fit on **train only**), and `train_models()` — RF (fixed) + XGBoost/LightGBM tuned by rolling-origin `TimeSeriesSplit(5)` over train+val, **refit on train only**. No shuffle; seed 42. |

### `src/evaluate/`
| File | How it works |
|---|---|
| `metrics.py` | Regression metrics, percentile **bootstrap CIs**, seasonal (monsoon-calendar) split, residual ACF, AQI classification, and the paired tests vs persistence: `paired_bootstrap_diff` (ΔMAE/ΔRMSE CIs) + `diebold_mariano` (HLN-corrected) + `significance_vs_persistence`. |
| `interpret.py` | TreeSHAP summary/dependence + permutation importance for the best model. |
| `plots.py` | Diagnostic figures: pred-vs-actual, residual ACF, residual-vs-features, confusion matrix. |
| `rolling_backtest.py` | Supplementary **6-fold expanding-window backtest** (train ≤Dec31 y, test y+1, for y=2019..2024). Reuses the builder/tuning/metrics; writes `reports/rolling_backtest.csv` + figure. Counts how many folds each model beats persistence on paired ΔRMSE. |

### `src/` top-level scripts
| File | How it works |
|---|---|
| `run_experiment.py` | One command — `python -m src.run_experiment --config config/model.yaml` — runs the full headline pipeline: features → train → evaluate (CIs, seasonal, significance, SHAP, permutation) → writes every artifact in `reports/` and `models/`. The notebook 02 Step-7 cell calls the same `evaluate_and_save`. |
| `freeze_model.py` | `python -m src.freeze_model` refits XGBoost on train (≤2023) and writes the immutable `models/final/` pack + `SHA256SUMS`. |
| `predict.py` | Shared inference core + CLI: `python -m src.predict --date YYYY-MM-DD` loads the frozen artifacts, builds the day-t feature row, outputs next-day PM2.5 + AQI. Refuses dates whose features are unavailable. Also exposes `verify_checksums` / `predict_series` used by the app. |

## `app/` — Streamlit demo (read-only display layer)
| File | How it works |
|---|---|
| `streamlit_app.py` | `streamlit run app/streamlit_app.py`. Read-only over `models/final/` + the processed master; uses the **same** `src/predict.py` code path (app↔CLI parity). Verifies `SHA256SUMS` at startup (red banner + refuses to predict on mismatch). Four pages: **Forecast** (pick a date → next-day PM2.5 + AQI, with observed value + error when present), **Model performance** (metrics/CIs, significance, seasonal, backtest figure — read from `reports/`), **Recent forecasts** (90-day observed-vs-predicted overlay), **About** (renders `docs/MASTER_DOCUMENTATION.md`). Permanent "research demonstration, not operational" banner. |
| `README.md` | Launch notes, what each page shows, and the explicit note that public deployment is out of scope for this phase. |

## Quickstart (see `docs/MASTER_DOCUMENTATION.md` Part 11 for full detail)

```bash
pip install -r requirements.txt                 # keys: OPENAQ_API_KEY + FIRMS_MAP_KEY in .env; CDS token in ~/.cdsapirc
jupyter nbconvert --execute --inplace notebooks/01_data_acquisition.ipynb   # ingest (auto BLH patch)
python -m src.run_experiment --config config/model.yaml                     # headline results
python -m src.evaluate.rolling_backtest --config config/model.yaml          # multi-year backtest
python -m src.freeze_model --config config/model.yaml                       # freeze published model
python -m src.predict --date 2025-06-01                                     # inference (CLI)
streamlit run app/streamlit_app.py                                          # interactive demo
pytest -q                                                                   # tests
```
